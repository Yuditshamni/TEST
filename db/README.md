# db/ — database objects

How every object in the DEV database looks **now**. One object = one file = one `CREATE`.

```
db/
  <SCHEMA>/
    Tables/<OBJECT>.sql
    Views/<OBJECT>.sql
    Procedures/<OBJECT>.sql
    Functions/<OBJECT>.sql
  DEV_MAP.md           generated by tools/dev_map.py: boxes and arrows, bronze → silver → gold
```

- The file is named exactly as the object. To change an object, edit its file.
- **Every change also gets a numbered migration** in `scripts/migrations/`: the object file says where we are, the migration says how an environment gets there (`scripts/README.md`).
- Grants → `scripts/grants/`. Config rows → `scripts/seed/`.
- Nothing temporary here: a try-out is a temp table, or `TRY_` on a branch (`nogamy-db-objects`).

If the platform has its own project format for database code (a database project, a dbt project, a schema-compare export), keep that format in this folder instead, and say so in `_context/platform.md` §6. The rule stays: one object, one file, in Git.
